# 会话自动命名

增强 DSH 原生的自动标题请求，使用「类型 · 具体任务」格式，例如 `排查 · 会话切换时页面闪白原因分析`。

## 行为

- 通过公开的 `llm/stream` 中间件，只处理 `purpose: session-title`；主对话不等待标题生成。
- 复用宿主原生标题 provider，不重复注册。原生服务负责触发时机、手动标题保护、历史记录和侧栏投影。
- 保留请求的模型、输入和已有思考强度。缺省强度时，使用模型声明的默认值；没有默认值、且模型只提供思考等级时，选用第一个声明等级。不会硬编码某家模型的等级。
- 将标题输出预算提高到至少 2048 tokens，给思考内容和标题正文留出空间；仍遵守原生请求的超时和取消信号。
- 遇到 429/RATE_LIMIT 最多重试三次，分别等待 1.5、3、6 秒。每次尝试的响应独立缓存，避免失败片段混入结果；关闭补丁会取消请求和等待。
- 标题必须符合固定类型、单行格式和 40 字符上限，否则保留原有标题。宿主自己的 UTF-8 字节上限仍然生效。
- 关闭后恢复原生命名规则；已经生成的标题保留。默认原生 first-prompt provider 仅自动命名新建非分支会话的首条需求，不批量改写旧会话。

## 接入与诊断

通过独立的 `ctx.inject(['llm'])` 子作用域访问 LLM 服务。原生请求对象已冻结，所以复制并改写请求，经公开服务重新派发；对象身份标记防止中间件递归。正常情况下只发送一次标题模型请求。

`format` API 返回格式及最低输出预算；`status` 返回本次启用后的请求、成功、失败、重试次数和最后的终止原因，便于区分“补丁未加载”“收到请求但调用失败”和“正常完成”。它们沿用插件统一的本机请求校验。诊断不包含聊天内容，错误信息限长并过滤常见密钥格式。

原生 `session/title-llm-request` 日志记录的是中间件改写前的提示词和预算；实际请求会使用本补丁的提示词、预算和兼容的思考强度。不要将该原生日志当作最终发往模型的请求。

## 桌面实测（2026-09-08）

通过用户本机的 DeepSeek Harness 桌面 App 启动器进行验证，使用实际 Web profile 和 `z-bigmodel / glm-5.3-flash`：

1. 会话 `session-61c59802-02bd-455c-91af-9c6eefa3ced7` 自动变为 `设计 · 会话搜索功能方案`，侧栏及窗口标题同步更新。
2. 会话 `session-f923f751-9b6d-42d9-8a18-41aecf15d40e` 自动变为 `排查 · 会话切换时页面闪白原因分析`。持久化事件表明，标题在请求开始约 16.6 秒后生成，主回复约 49.5 秒结束，标题早于主回复约 32.9 秒。
3. 复现并修复真实模型返回的 HTTP 400：该模型必须思考，省略思考强度的标题请求被转换为关闭思考而遭拒绝；另覆盖实际遇到的 HTTP 429。
4. 完全退出桌面应用后再次通过同一启动器打开，两个自动标题均保留，后端 `format` 接口确认加载最终补丁及 2048-token 最低预算。最终 111 项测试、构建和打包检查通过。
